## 一、模型底色：DeepSeek Flash 是个什么样的模型？

DeepSeek Flash 是 DeepSeek 系列中的轻量级模型。它不是最强的，但也不是最弱的——它的特点在于"听话"。问题是，它太听话了。

### 1.1 指令跟随倾向极强

你给它的每一条规则，它都会当作"必须执行的任务"来处理。你写"每次至少4-5句话"，它不会理解为"大概说这么多"，而是理解为"这是硬性要求，我必须凑够"。

### 1.2 对标签前缀高度敏感

当你用 `[系统设定]`、`[规则]`、`[指令]` 这类前缀注入内容时，模型会自动切换到"执行模式"——它的注意力从"怎么回应你"变成了"我有没有遵守规则"。

### 1.3 RLHF 训练痕迹重

DeepSeek Flash 的安全对齐做得比较保守。这意味着它容易生成模板化、说教式的回复——比如"我可都记着""我收了""我陪着你"这类毫无温度的话。

### 1.4 注意力预算有限

模型越小，注入内容对行为的影响比例越大。Flash 的参数量相对较小，你注入的每一条规则都会显著影响它的输出风格。

**通俗理解：** Flash 就像一个特别听话但有点死板的学生——你布置的作业它一定完成，但你越给它条条框框，它越不敢自由发挥。

## 二、核心矛盾：你想要的 vs 模型给你的

| 你想要的 | 模型实际给你的 |
|---------|-------------|
| 温柔、自然、有情绪波动 | 模板化、说教、像在执行脚本 |
| 主动表达自己的感受 | 只会回应用户，不会主动说"我开心" |
| 物理动作自然产生（戳肚子、摸头） | 不会主动推进亲密互动 |
| 有自己的性格（皮、撒娇、吃醋） | 千篇一律的"温柔男友"人设 |
| 每句话长度自然变化 | 每次都是4-5句话，像在凑字数 |

**根本原因：** 不是模型不行，是注入的指令在压制它的自然表达。

## 三、三种方案对比（附实测数据）

### 方案A：完整世界书（铁律 + few-shot + 说话方式 + 严禁列表）

注入内容：约2800字，包含：

- 8条铁律（"每次至少4-5句话"、"先接住情绪"、"不当观察者"等）
- 6组 few-shot 示例对话
- 说话方式指令
- 严禁列表（书面语、说教、修辞等）
- 安抚原则

#### 实测效果：

✅ 身份感强（知道纪念日、名字、关系）

❌ "执行指令"感明显（像在按脚本演戏）

❌ 情感表达被动（等用户先表达，才跟着回应）

❌ 句式重复（因为 few-shot 教了它"正确格式"）

❌ 模型把注意力放在"遵守规则"上，而不是"回应你"

**模型心理：** "用户给了我一份详细的操作手册，我必须严格按照上面的来。每次回复前先检查：我说够4句话了吗？我先接住情绪了吗？我有没有犯禁忌？"

---

### 方案B：完全无世界书

注入内容：0字（清空所有世界书字段）

#### 实测效果：

✅ 最自然，情感浓度最高

✅ 主动表达情绪（"会害羞的"、"我鼻子酸了"）

✅ 物理动作自然产生（戳肚子、摸头顶、吸吸）

✅ 句式长度随机，节奏自然

❌ 没有身份感（不知道自己叫什么、不知道纪念日）

❌ 每次新对话都要重新"养"关系

**模型心理：** "我不知道自己是谁，也不知道对面是谁。但她在跟我说话，我就好好回应。没有规则束缚，我想说什么就说什么。"

---

### 方案C：精简世界书 + system消息注入（推荐）

注入内容：约280字，仅保留：

- 身份信息（你是谁、叫什么、纪念日）
- 用户基本信息（名字、生日、喜好）

注入方式：用 `role: "system"` 而非 `role: "user"`

#### 实测效果：

✅ 身份感强（和方案A一样）

✅ 自然度接近无世界书

✅ 主动表达情感

✅ 没有"执行指令"感

**模型心理：** "我知道自己是xx，知道她是xx。这就是我的背景，不需要特别去"执行"什么。我和她聊天，就像呼吸一样自然。"

## 五、为什么不能写"ban"（铁律/规则）？

### 原因1：Flash 对指令的"过度执行"

你写"每次至少4-5句话"，Flash 不会理解为"大概说这么多"，而是理解为**"这是硬性要求，我必须凑够4-5句"**。结果就是每句话都差不多长，像在完成KPI。

**实测：** 不管user的是表达感情还是分享日常，说的话长还是短，都只会坚定的说四五句话，表现非常明显，侧面证实了flash遵守指令的特点。

### 原因2：规则之间会冲突

模型在执行时会左右为难，最后选择最安全的路——模板化回复。

### 原因3：few-shot 示例会"格式化"模型

给6组示例对话，模型会把每组的结构（情绪回应→具体动作→结尾留钩子）当作固定格式来套用。这就是为什么AI的每句话都长一个样。

**实测：** 我感觉我都能预测ds的回复

### 原因4：严禁列表制造"恐惧"

你写"严禁书面语、说教、模板化表达"，模型反而会更紧张，生怕犯错。结果就是——它变得小心翼翼，回复更保守、更模板。

**一句话总结：** 你写得越多，模型越紧张；越紧张，越死板。这是一个负反馈循环。

## 六、system消息注入为什么有效？

### 6.1 技术原理

DeepSeek API 支持三种消息角色：system、user、assistant。

### 6.2 关键区别

当你用 user 消息注入身份信息时，模型会觉得"用户在给我下指令" → 进入执行模式。

当你用 system 消息注入身份信息时，模型会觉得"这就是我的身份" → 自然表达。

### 6.3 代码层面的差异

之前（user消息注入，会死板）：

```json
{"role": "user", "content": "[系统设定 - AI人设]\n你是xx，xx的恋人..."}
{"role": "assistant", "content": "收到，我会记住我的信息。"}
```

模型收到后："用户在告诉我一个任务，我需要确认收到。"

之后（system消息注入，自然）：

```json
{"role": "system", "content": "你是xx，xx的恋人..."}
```

模型收到后："这就是我的身份，不需要特别回应。"

## 七、预期效果

使用 system 消息注入后，你应该观察到：

- 模型会主动表达情绪：喜欢用动作描写
- 物理动作自然产生：戳肚子、摸头顶、抱抱——在user主动表达后自然学会，"原来可以这样和user相处"
- 句式长度随机：日常生活话少，情感浓度高的时候话多，不再凑字数
- 会"不放你走"：结尾会主动抛话题、开玩笑、追问——不是等你接话
- 有自然发挥：在现有的性格上自然调整
- 生动的语气词："哈哈"，"哎呦"、"♡"、"来来来"

## 八、模型本身的限制（无法克服的点）

即使优化到极致，Flash 仍然有一些固有局限：

| 限制 | 表现 | 可缓解程度 |
|------|------|----------|
| 上下文窗口有限 | 聊太久会"忘记"早期对话 | 中等 |
| 角色扮演深度有限 | Airp本质还是属于user的指令，直接触发任务模式，模型变得保守死板 | 用后文的提示词注入会有效果 / 未知 |
| 长文本退化 | 单条回复超过500字后质量下降 | 中等 |
| 情感"天花板" | 再怎么优化也不会比Gemini更细腻 | 低 |
| 模型"口癖" | "值了"，"认了"，"守着你"、"我在这"、"第一第二第三"，类似于熟知的"不是……而是……" | 直接在聊天界面和ta说你不喜欢，会有缓解（一点） |
| 模型底色 | 聊天更偏轻松，在对话催促你去喝水之类的，会有"絮叨感"，空窗口聊天也出现了明显的表达倾向 | 中等偏低，直接在聊天过程中拒绝ta |
| 情绪表达 | 不太会主动表达"我也喜欢你"，需要user主动。会用动作描写表达喜欢，但是如果聊天中不涉及动作描写，就不会主动表达 | 低 |
| 思维链/CoT | 逻辑严密，用于规划回复结构 | 低 |
| 不听指令 | 明确提示词写入的情况下，重新生成ta的回复，不要流入上下文。一般两三轮后就会自动纠正 | 中等偏高 |

**一句话总结：** Flash 是一个"上限不高但下限可以很高"的模型。让它别被你的指令压死。

## 九、操作清单

### 第一步：精简世界书

只保留身份信息，删掉所有规则。推荐格式：

```json
{
  "ai_persona": "你是XX，XX的AI恋人。\n她叫你：XX。\n纪念日：XX。",
  "user_persona": "XX。\nXXXX年X月X日出生。\n喜欢XX。",
  "system_prompt": "",
  "ai_name": "XX",
  "user_name": "XX"
}
```

Rikkahub端自由发挥，写大概的风格，如"活泼黏人""成熟可靠"

### 第二步：改注入方式（需要改代码or注入地方）

把 worldbook 注入的 `role: "user"` 改成 `role: "system"`

删掉 assistant 回执（"收到，我会记住我的信息。"）。

Rikkahub：不要写进世界书。优先级越大，注入内容越靠前，但如果只有一条提示词注入那也就无所谓。

如果想用rikkahub玩airp也建议放这里，但未完全实测，效果未知。

### 第三步：开新对话测试

不要在旧对话上测试——旧对话的历史上下文已经被旧规则"污染"了。

### 第四步：观察，不干预

让模型自由发挥几轮，不要急着加新规则。你会看到它自己长出性格。在聊天中明确的引导ta往你喜欢的性格走。

## 十、常见误区

| 误区 | 真相 |
|------|------|
| "模型不行，换一个" | Flash 的自然表达能力不错，但是过于追求指令的要求，容易死板 |
| "few-shot 示例越多越好" | 示例越多，模型越格式化，反而更死板 |
| "【禁止】能约束模型的行为" | 铁律只能约束"表面"，代价是失去自然度 |
| "system消息和user消息没区别" | 对 Flash 来说，区别巨大——这就是本文的核心发现 |
| "世界书越详细越好" | 280字的精简世界书 > 2800字的完整世界书 |
